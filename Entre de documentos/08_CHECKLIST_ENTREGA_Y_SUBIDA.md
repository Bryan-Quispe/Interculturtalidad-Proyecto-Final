# Checklist de entrega y subida

## 1. Entregables pedidos por la evaluación

| Entregable | Estado | Dónde está |
| --- | --- | --- |
| Sistema funcional | Preparado | Carpetas `frontend` y `backend`. |
| Código fuente | Preparado | Repositorio del proyecto. |
| Presentación | Preparada | `Presentacion.pdf` y anexos. |
| Documentación del proceso | Preparada | Carpeta `Entre de documentos`. |
| Repositorio del proyecto | Preparado si se sube a GitHub | Usar enlace del repositorio si aplica. |

## 2. Archivos recomendados para subir

1. `DOCUMENTACION_COMPLETA_MASCOTAS_3D_SCRUM.pdf`
2. Carpeta completa `Entre de documentos`.
3. `Presentacion.pdf`.
4. Código fuente comprimido o enlace de repositorio.
5. Anexos Scrum y calidad, si la plataforma permite varios archivos.

## 3. Orden recomendado de defensa

1. Problema.
2. Usuarios.
3. Solución tecnológica.
4. Enfoque intercultural.
5. Demostración del sistema.
6. Proceso Scrum.
7. Calidad técnica.
8. Limitaciones y mejoras futuras.

## 4. Verificación antes de exponer

- Abrir frontend.
- Confirmar backend levantado.
- Probar login.
- Abrir una mascota de demostración.
- Cambiar idioma a kichwa.
- Cambiar idioma a modo bilingüe.
- Abrir modelo 3D.
- Preparar cartel.
- Descargar PDF.
- Confirmar que el PDF no muestra coordenadas exactas.
- Tener lista la respuesta sobre Git.

## 5. Respuesta breve sobre Git

Si preguntan por qué los commits no muestran todo el periodo:

> "El repositorio se formalizó al final del proyecto, por eso Git no es nuestra evidencia cronológica principal. El proceso se evidencia con la documentación Scrum: cronograma, backlog, bitácora, reviews, retrospectivas, incrementos, pruebas y cambios registrados. La mejora para próximos proyectos es iniciar el repositorio desde el día 1."

## 6. Para aspirar al nivel excelente

Durante la exposición, no basta con decir que el sistema funciona. Hay que mostrar:

- Qué problema real resuelve.
- Qué usuarios se benefician.
- Cómo el enfoque kichwa-castellano aporta valor real.
- Qué se planificó en Scrum.
- Qué cambió por revisión del incremento.
- Qué decisiones técnicas protegen privacidad y calidad.

## 7. Revisión final de carpeta

La carpeta debe contener:

- Documentos `.md`.
- Versiones `.pdf`.
- Anexos.
- Archivo `.zip` para subir.
- Rúbrica original como referencia.
